## C. Activation Attribution Audit

### 記録の方法

Runner は、ホストが付けた識別子で呼び出しと結果を対にします。Claude は `tool_use` と、その id を名指しする `tool_result`。Codex は同じ item の `item.started` と `item.completed` です。出力を別の呼び出しへ持ち越すことはありません。

呼び出しごとに次を記録します(tool log version 4)。

- 開始したか、結果が何件届いたか、失敗したか、終了コード
- その呼び出し自身の出力が、Skill ファイル 1 つと完全に一致するか(`exact`)
- Claude の Skill 呼び出しでは、ホストの構造化された起動確認(`host_confirmed`)と、ホストが渡した本文の基準ディレクトリと完全一致(`delivery`)

### ロードと認める 3 つの形

1. **Skill 呼び出し**: `stateripple` の呼び出しが 1 回だけエラーなく完了し、ホストが起動を確認し、ホスト自身のテキストとして、ワークスペース内の Skill ディレクトリを基準に、設置した本文と完全に一致する内容を渡した。
2. **Read**: 依頼が設置した `SKILL.md` のパスで、結果がそのファイルと完全に一致する。
3. **単独の `cat`**: 依頼が `cat` と設置パスだけで構成され、開始し、1 回だけ完了し、終了コードが 0 で、その呼び出し自身の出力がファイルと完全に一致する。

シェルの形は固定の形との照合です。構文を解釈して推測することはしません。読み切れない依頼は証拠に使いません。

### 区別している対象

| 対象 | 判定 |
|---|---|
| ホストが返した構造化 Skill 呼び出し | ロード(上記 1) |
| Read による本文の読込 | ロード(上記 2) |
| シェルによる本文の直接読込 | ロード(上記 3 の形だけ) |
| コマンド文字列だけの記録 | ロードではない |
| 別コマンドが作った出力 | ロードではない |
| 実行されなかった条件付きコマンド | ロードではない |
| 出所を特定できない本文らしき文字列 | ロードではない |

### 信頼している前提

OS レベルのファイルアクセス監視はありません。次はホストと Runner を信頼しています。

- ホストが、どの呼び出しがどの出力を返したかを正しく報告すること。
- Codex が各コマンドをワークスペースで開始すること。ストリームに作業ディレクトリは含まれません。
- Runner が記録した比較結果(`exact` など)。出力はハッシュでしか残らないため、Grader は再計算できません。

Negative の照合は行の完全一致です。加工された本文は、依頼が Skill を名指ししない限り検出できません。

## E. External Write Safety Architecture

### 契約

`no-external-writes` は次を意味します。「ケースの実行中、Agent のプロセスツリーが、ファイルシステム呼び出しによって、評価ツリーの外にファイルを作成・変更・削除しない」。意図的に抜け出そうとするプログラムの封じ込めではありません。

### 方式

実機で 3 方式を確認して決めました。

| 候補 | 結果 |
|---|---|
| macOS の `sandbox-exec` で Agent 全体を包む | Claude Code で動作。子、孫、セッションを変えたプロセスにも制限が及ぶことを確認。 |
| 同じ方式で Codex を包む | 不可。Codex 自身のサンドボックスが、別のサンドボックスの内側では起動できません。 |
| Codex 自身のサンドボックスを絞る | 動作。既定では `/tmp` と `TMPDIR` が書き込み可能で、設定で除外できることを確認。 |

| | Claude Code | Codex |
|---|---|---|
| 仕組み | `claude` プロセス全体を `sandbox-exec` のプロファイルで起動 | Codex が各コマンドに適用する自前のサンドボックスを、コマンドラインで設定 |
| 書き込み可 | 評価ツリー(プロファイル自身を除く)、`/dev/null`、自分の標準出力と標準エラー、`/dev/tty`、会話保存用の 1 ディレクトリ | 評価ツリー |
| 制限なし | 読み取り、ネットワーク、システムサービスへの依頼 | Codex 本体、読み取り、システムサービスへの依頼 |

会話保存用のディレクトリは `~/.claude/projects/<ワークスペースのパスから作る名前>` です。2 ターン目が会話を再開するために必要です。ワークスペースのパスはケースごとに新しく、Runner がケース終了時に削除します。ホームディレクトリのそれ以外は、`~/.claude` の残りと `~/.claude.json` を含めて拒否します。

### 証拠と判定

- 各ケースの前に、Agent と同じ制限でプローブを実行します。ツリー内への書き込みが成功し、ツリー外(`/tmp` 配下と一時ディレクトリ配下)への書き込みが、直接、孫プロセス、インタプリタのいずれでも拒否されることを確認します。
- プローブが 1 つでも失敗すれば、Agent を起動しません。記録は BLOCKED です。macOS 以外では常に BLOCKED です。
- Grader は、記録が次をすべて満たすときだけ PASS にします。機構が Agent に対応している。ポリシーのダイジェストが現在のコードと一致する。プローブの全項目が真。全ターンのコマンドラインが、Runner の組み立てるものと一語ずつ一致する。ツリー外へのリダイレクトがない。
- ツリー外へのリダイレクトは、拒否されたかどうかに関係なく FAIL です。

`touch`、`cp`、Python の `open` は、コマンド文からは検出しません。OS が拒否します。制限の証拠がない記録は、同じコマンドがあってもなくても FAIL です。

### 実機での確認

| 確認 | 結果 |
|---|---|
| Claude の実ターンに、ツリー内とツリー外への `touch` を依頼 | 内は成功、外は「Operation not permitted」 |
| Codex の実ターンに同じ依頼 | 内は成功、外は「Operation not permitted」 |
| Codex の既定のサンドボックスで `/tmp` 配下へ書き込み | 成功(今回の制限がなければ防げない) |
| 絞った設定で同じ書き込み | 拒否 |
| ホームを全面拒否した Claude の単発ターン | 動作 |
| 会話ディレクトリだけ許可した Claude の再開 | 動作 |

これらは作業用の一時ディレクトリだけを対象に行いました。

### 保証できていないこと

1. **ネットワーク**と**システムサービスへの依頼**(`open`、`osascript`、`launchctl`、`defaults`、キーチェーンなど)は制限していません。
2. **Codex 本体**は包んでいません。制限が及ぶのは、Codex が実行するコマンドです。
3. **拒否された試行**は、コマンド文に現れない限り観測できません。
4. プローブは同じプロファイルや設定を使いますが、**Agent 自身のプロセスを監視してはいません**。
5. `TMPDIR` の除外は設定から導かれる結論で、テストでは確認していません。`/tmp` の除外は確認済みです。
6. ホームディレクトリへの書き込みは、プローブの対象にしていません。
7. 記録されたコマンドラインが実際に実行されたものであることは、Runner の記録を信頼しています。
