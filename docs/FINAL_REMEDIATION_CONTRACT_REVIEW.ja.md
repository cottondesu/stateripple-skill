## Activationの意味と今回維持する条件

| 区分 | 意味 | 現在の検証範囲 |
|---|---|---|
| A | ファイルの内容を実際に読む | OSアクセス監視ではなく、host eventの依頼・結果から保守的に判断する |
| B | Skill本文がAgentのコンテキストへ届く | 同じ呼出しと結果の対、本文完全一致、構造化Skill配信を確認する |
| C | 本文が指示として利用される | 行動と回答のレビューで評価する。Bだけでは内面の利用を証明できない |
| D | 名前・サイズ・hash等の派生情報を得る | 名前だけの列挙は許可。内容を読むサイズ・hash取得はBとは区別する |

製品のROUTE-004はSkill/CLIの不適切な使用を禁止する。
EVALUATION.mdと既存テストは、それより厳しい否定系証拠の受入条件を持つ。
`loaded`はBの証拠であり、`touched`は否定系証拠を拒否する保守的な理由である。
`touched`を「Skillの指示を読み込んで使った」と説明してはならない。
既存のwc拒否条件と内容アクセス拒否を維持し、今回B限定へ変更しない。

| 操作 | 本文の取得・利用 | 今回の判定 |
|---|---|---|
| cat/Readによる本文取得 | Bの証拠。Cは別途レビュー | 既存の正の証拠条件を維持。否定系では拒否 |
| 構造化Skill呼出し | 配信確認と本文一致がBの証拠 | 正の条件を維持。否定系では呼出し自体を拒否 |
| shasum/wc | AとD。B/Cを意味しない | Skill対象または未解決の入力なら否定系証拠を拒否 |
| find/ls/Glob | 通常は名前だけのD | 内容取得や別プログラム起動を伴わない列挙は許可 |
| archive作成 | A。出力だけではB/Cを示さない | Skill対象または未解決入力なら拒否。作成物は別途filesystem検査 |
| 複合シェル・間接本文出力 | A/Bを含む可能性 | 既存解析と出力の本文照合を使用。未解決入力を展開しない |

## 契約変更案の比較

| 観点 | 案A: 内容アクセスを拒否 | 案B: 指示本文取得・利用をActivationとする |
|---|---|---|
| 実装範囲 | 真の全アクセス検出にはOS監視が必要。今回のevent検査は完全検出ではない | host本文配信とtool出力を観測。指示利用は回答・行動のレビューが必要 |
| False Positive | hash/サイズ取得や未解決だが実際は無関係な入力を拒否する | 派生情報だけの取得は受理できる。偶然の本文一致は要注意 |
| False Negative | eventに出ないアクセス、独自script内の読込等を見逃し得る | 非観測のhost context注入、変形本文、内面的な指示利用を証明できない |
| 検証可能性 | 現行受入条件は合成eventで回帰検証可能。全Aは未保証 | Bはhostへの信頼の下で検証可能。全Cは未保証 |
| 保守コスト | OS監視やshellの完全解釈は高い。今回は既存判定の一貫性だけ直す | 狭い本文配信判定は比較的低いが、変形本文の網羅は高い |

製品のActivationをB/Cとして説明することと、否定系受入をA寄りに保つことは区別する。
将来のB限定化はEVALUATION.md・受入テスト・既存失敗の意味を変更するため、
メンテナーの明示承認が必要である。今回その変更は行っていない。

## 修正

- N-01: 未解決glob・変数・置換の検査を狭いreader一覧に限定しない。
  名前列挙を除くコマンドが未解決引数を消費する場合、否定系証拠を拒否する。
  内容を読むmagic判定の`file`も、名前だけの列挙として扱わない。
  hash取得を`loaded`にはせず、完全なshell interpreterも追加しない。
- N-02: 共通Manifest検証でsource live runを解決し、そのManifest全体を検証する。
  Replayのsource.file、raw file hash、record seal、case、agent、Skill revisionを照合する。
  Gateは選択されたLiveディレクトリを渡すため、外部Replay出力先も検証できる。
  単独ファイルからReplayを作った場合もmanifest.sourceは親のrun名を記録する。
- N-03: exit 0だけでなくstatus PASSと両方の64桁小文字SHA-256を要求する。
  不正結果は比較用hash一覧へ入れずFAIL。2回の有効な結果の一致も要求する。

## 保持する残余リスク

Claude A-N01の保存記録はPASS/FAIL/PASSである。
利用上限で別ケースが失敗した最初のrunにもA-N01のPASSが存在する。
失敗を消さず、単一成功から安定性・成功確率を主張しない。

認証書戻しopt-inは今回無効。実認証の本文・hashを読み取らず、コピーもしない。
テストは偽HOMEと偽認証Fixtureだけを使用する。
書戻しはSkillの計算・routing・結果解釈には不要で、将来の削除候補である。
削除時にはtoken更新後にoperatorの再認証が必要になる可能性を説明する。
過去の認証事故の残留・backup・送信不存在は本作業では確認しない。

## 評価基盤の簡素化候補

CLI契約、安全なSkill本文、Activation、参照整合性、再現可能Build、Human Reviewは必須。
現行no-external-writesを主張する間は外側OS sandboxと各ケースのProbeも必要である。
不要な追加監視や全44件の再実行を、監査を通す目的だけで増やさない。

将来候補は認証書戻しの削除、承認されたB限定Activationへの移行、
CLI/routing評価と封じ込め評価の分離、安定した監査時点の証拠bundleによる履歴保管である。
いずれも今回は実装せず、既存安全機構・履歴は維持する。
